# Quoting a response

Select text in an assistant response and choose **Quote selected text**. The button follows the selection. HAPI chooses an input format for the integration carrying that conversation.

For Codex and Codex Native, the selection appears as a quote card above the message body. Each card has its own **Notes for quote** field. Add a question or comment to that selection, edit the main message separately, or remove individual cards. Notes use Desktop's existing `annotation` field. The complete serialized draft retains each selection's text, notes, and verified native source through draft persistence, queueing, and failed-send recovery. Sent cards display the same notes.

## Input protocols and evidence

Checked on 2026-11-01 against HAPI's integration code and the official sources below. A provider's desktop or terminal UI can offer a quote chip without exposing the same structure through the SDK, ACP, or headless interface HAPI uses. This table records verified input surfaces; a text fallback does not assert that the provider's other products lack quoting.

| Integration | What HAPI sends and what was verified | Current quote format |
| --- | --- | --- |
| Codex / Codex Native | Ordinary app-server text input containing the installed Desktop `response-annotations` envelope. It has per-selection `text`, optional `annotation`, and optional source item/range. [Installed protocol evidence](./codex-native-requests.md#selected-response-annotations). | Desktop envelope, quote cards, and per-selection notes. Native sources are attached only when the real item and offsets are known. |
| Claude Code | HAPI's SDK bridge sends `message.content` as text. The official `SDKUserMessage` also documents generic content/paste inputs; the checked interface does not establish a prior-assistant selection ID/range protocol. `parent_tool_use_id` concerns tool/subagent attribution. [Agent SDK reference](https://code.claude.com/docs/en/agent-sdk/typescript#sdkusermessage). | Plain text blockquote. No proprietary quote wrapper inferred from Claude's UI. |
| Cursor Agent | ACP `session/prompt`. Cursor documents text prompts and extensions for questions, plans, todos, tasks and generated images. No selected-response input extension was verified in that documented set. Legacy HAPI sessions still pass text through `agent -p`. [Cursor ACP](https://cursor.com/docs/cli/acp). | Plain text blockquote. |
| Grok Build | HAPI uses `grok agent stdio` and ACP prompts. The official integration surface is ACP, rather than the consumer Grok chat API. No selected-response primitive was verified on this path. [Headless and scripting](https://docs.x.ai/build/cli/headless-scripting). | Plain text blockquote. |
| GitHub Copilot | HAPI uses `copilot --acp --stdio`. The official example sends text blocks to `session/prompt`; supported slash commands are separately advertised. [Copilot ACP server](https://docs.github.com/en/copilot/reference/copilot-cli-reference/acp-server). | Plain text blockquote. |
| Kimi | HAPI uses `kimi acp`. The official CLI reference defines the ACP integration. No provider-specific selection reference was verified on HAPI's ACP input path. [Kimi ACP reference](https://moonshotai.github.io/kimi-cli/en/reference/kimi-acp.html). | Plain text blockquote. |
| OpenCode | ACP supports structured text, images and resources. OpenCode documents how each block is passed to the model; generic resource context does not by itself identify a selected range in an earlier response. [OpenCode ACP prompt content](https://opencode.ai/v2/docs/cli/acp/#prompt-content). | Plain text blockquote through HAPI's current text prompt adapter. |
| DeepSeek Harness | HAPI uses the `dsh --profile acp` automation profile. The inspected installed ACP adapter accepts text/resource links, validates images, and rejects embedded resources. No selection-reference input was verified. [Official project](https://github.com/deepseek-ai/deepseek-harness). | Plain text blockquote. |
| Pi | HAPI uses RPC `prompt`/`steer`/`follow_up` with a string `message` and optional images. The checked command surface does not establish a selected-response source/range field. [Pi RPC commands](https://pi.dev/docs/latest/rpc-commands#prompt). | Plain text blockquote. |
| Antigravity | The App explicitly supports selection quote chips, while the same official comparison lists selected text as unavailable in the CLI. HAPI uses the documented `agy -p` headless text path. [Mentions and quoting](https://antigravity.google/docs/at-mentions/#quote-a-selection), [headless input](https://antigravity.google/docs/cli/headless/). | Plain text blockquote in the CLI integration. The App's quote capability is acknowledged separately. |

ACP does have content `annotations`, but these are MCP metadata hints about content usage/display. They are distinct from Codex's response-selection records. ACP also provides resource links and capability-dependent embedded resources for general context. HAPI's common `PromptContent` adapter currently admits text, so sending a new resource block would require an explicit transport change and the agent's advertised support. HAPI does not fabricate resource URIs or reinterpret MCP annotations as response message IDs. [ACP v1 content specification](https://agentclientprotocol.com/protocol/v1/content).

The quote capability resolver keeps this decision separate from the selection control. A newly verified provider input format can be added without copying Desktop's private syntax into unrelated integrations. No model-input smoke test was sent during this investigation.
