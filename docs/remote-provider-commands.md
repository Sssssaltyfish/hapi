# Remote provider command capabilities

The remote runner resolves `/compact`, `/approve`, `/recap`, and `/usage` before ordinary model input. Exact command names with whitespace or end-of-input are recognized; filenames such as `/compact.md` are ordinary input. Project commands, installed command templates, discovered skills, and provider-reported executable commands retain ownership of their names.

| Provider | `/compact` | `/recap` | `/usage` | `/approve` |
| --- | --- | --- | --- | --- |
| Codex | Native `thread/compact/start` on an idle conversation | Ephemeral structured helper with bounded visible history and tools disabled, matching the CLI workflow | Native account usage and rate-limit reads | One retry of the exact observed automatic-review denial |
| Claude | Existing native SDK slash-command path; optional native instructions preserved | Native `--resume --fork-session` side query, no tools or persistence | Classified session facts and native rate-limit observations when supplied | Existing approval cards for pending tool requests and session permission controls |
| DSH | Public native command registry through the HAPI ACP adapter extension; native argument grammar is preserved | Not provided by the installed native registry | Latest reported usage/context facts | Native `/permission` presets and pending request approval cards |
| AGY | No safe headless compaction operation is integrated | No isolated recap operation is integrated | Latest usage reported in streamed step/result envelopes | Pending tool requests use the existing approval cards |
| Pi | Existing native compact RPC, including custom instructions | Not integrated; discovered extension commands keep precedence | Live native `get_session_stats` query, with reported session totals; `/session` also remains available | Explains Pi RPC's automatic tool execution; discovered extensions retain their own commands |
| OpenCode | Existing native session summarization API | Not integrated | Latest reported session usage | Pending tool request approval cards and session permission controls |
| Cursor / Grok | Sent through the existing ACP command path only when the current ACP session advertises it | Only a provider-reported executable command can own this name | An advertised native command takes precedence; otherwise latest reported session usage | Advertised native `/approve` behavior takes precedence; otherwise pending request cards and provider controls |
| Copilot / Kimi | No new compaction operation is claimed | Not integrated | Latest reported session usage | Pending request approval cards and provider permission controls |

An unavailable built-in receives a local explanation and is not sent to the model as a chat prompt. `/approve` follows each provider's own behavior. A native command is sent with its original arguments; otherwise it leads to pending request approval cards or the provider's actual permission controls. It does not impose Codex's historical-denial retry semantics on other providers. A user-defined command with that name retains its existing provider behavior.

The command menu marks local approval navigation as `source: builtin`. Actual provider commands are merged as `source: plugin`, ahead of local fallback entries; project/user commands retain final precedence. DSH publishes its real command registry, including `/permission`. Cursor and Grok menus query the current ACP advertised command inventory. The web client can therefore preserve native/custom commands before using `/approve` to locate an existing approval card. Pi RPC has no per-tool approval prompt or runtime permission switch; its fallback explains that configuration rather than promising a pending action.

The local `/usage` report groups meaningful fields into tokens, context capacity, cost/duration, activity, and account limits. It does not print response JSON or raw wire field names. A provider's live read-only usage query is preferred when available; otherwise the source is explicitly the last report received by this running HAPI process. It is not a reconstructed session total. Before a report arrives it says that no usage is available. ACP context-only updates do not become fictitious zero-token bills. Claude synthetic API errors and subagent messages do not replace the main conversation snapshot.

Remaining context space is calculated only from a reported occupancy and measured capacity, and is labeled separately from account allowance. Guessed context denominators are excluded. Native Claude `rate_limit_event` utilization and reset facts, when present, appear as their own account window with the remaining percentage and reset time; an expired window is not presented as current remaining quota. When a provider does not report account limits or credits, the report explicitly says so. It does not fetch private account endpoints or infer quota from token counts.

Claude `/recap` requires an existing native conversation and accepts no arguments or attachments. Its prompt briefly asks what happened and what is next. Generated text has only leading and trailing whitespace removed: line breaks and longer useful responses are preserved. There is no character cap, forced single line, or output truncation for generated recaps. Claude's independent query reads a native fork, disables built-in tools and MCP servers, disables hooks and slash expansion, and uses `--no-session-persistence`. Its temporary native session ID is not adopted by HAPI. A timeout or session shutdown cancels the query; the main conversation's thinking state, model preference, and permission settings are not changed. This on-demand operation uses a model request and may incur provider usage.

Codex Native and managed sessions follow the CLI's ephemeral helper workflow. HAPI reads the latest nine turns through bounded history pagination, selects up to eight answered user/assistant exchanges and a newer unanswered correction, and preserves their order. Recognized Desktop message context is projected to visible text before summarization; tool results and private reasoning are excluded. The complete UTF-8 prompt is capped at 32,768 bytes, retaining both ends of long fields. The [upstream recap prompt](https://github.com/openai/codex/blob/94ca55a93c11348c6e3431e292b8e9a33dfefc82/codex-rs/context-fragments/src/recap_prompt.rs) asks for 40–60 words, at most 80, in the user's language, retaining unresolved validation and deployment caveats. Structured output requires a summary of at most 700 characters and a nullable next action of at most 200 characters. HAPI validates these fields and displays them without adding an English label.

Recap generation runs independently of ordinary input; Runner consumes the command immediately and reports its result or error when the background task finishes. Duplicate requests do not create another helper while one is running. A dedicated daemon connection starts an ephemeral thread with the source's model, provider and working directory. Built-in tools, MCP servers, hooks, plugins, skills, memories and background goal behavior are disabled. The helper generates the structured response through `turn/start`; it is never adopted as a HAPI session or projected into the source conversation. HAPI buffers matching helper events before the start response, rejects unexpected interaction requests, checks that the source remained idle and unchanged, and detaches the helper after success or failure. Timeout, cancellation and source changes interrupt a known running helper before detaching it. Unsupported hosts return an upgrade explanation. There is no sampling or raw-excerpt fallback and no second inference attempt.

The [official CLI implementation](https://github.com/openai/codex/blob/94ca55a93c11348c6e3431e292b8e9a33dfefc82/codex-rs/tui/src/app/recap.rs) orchestrates this workflow in its frontend; the daemon has no dedicated `/recap` RPC. `thread/sample` is a separate public experimental operation, first shipped in stable Codex 0.164.0, and is no longer used by HAPI's recap command. Read-only nonexistent-thread probes on 2026-11-06 confirmed that the running WSL 0.165.0-alpha.1.2 and Windows 0.166.0-alpha.5.1 daemons recognize sampling. The earlier unknown-variant report does not describe their current method recognition. `getConversationSummary` is catalog metadata, not generated recap text.

The [official Session recap documentation](https://code.claude.com/docs/en/interactive-mode#session-recap) distinguishes manual recap from the terminal's automatic return summary. Native automatic recaps require at least three turns, an unfocused terminal, and at least three minutes since a completed turn; they do not occur consecutively or in non-interactive mode. HAPI already forwards native `away_summary` records from terminal sessions. This change adds no background recap generation, timer, or automatic model request.

The [official auto-mode denial review](https://code.claude.com/docs/en/auto-mode-config#review-denials) is a native terminal operation on a specific blocked action. The [PermissionDenied hook](https://code.claude.com/docs/en/hooks#permissiondenied) tells the model it may retry during the current denial flow. HAPI's current SDK control surface approves a currently pending request by request ID. DSH's `permission` command changes native presets, and standard ACP permission responses decide live requests. These distinct provider operations are exposed according to their own contracts.

DSH command execution uses public `ctx.commands.list` / `ctx.commands.execute`, exact owned Agent identity, an idle session, and the original command's grammar. The ACP readable transport remains available during execution so `session/cancel` can abort the command. The default installed DSH registry exposes `compact`, `feedback`, `goal`, `permission`, and `plan`. A custom ACP server that does not advertise the HAPI command extension receives an explicit unsupported result for `/compact`. Attachments are not admitted for this adapter's native `/compact` path.

Verification used the installed DSH 0.2.0-rc.2 with a deterministic local LLM adapter: native `/compact` executed with its own command ID and returned “No compactable history yet.” without another `session/prompt`. The installed Claude CLI was tested against a local deterministic HTTP provider: the recap used a different session ID, offered no tools, and left every persisted source-conversation JSONL file and its hash unchanged. No external model or user conversation was used in those probes. Cursor/Grok executable command availability is determined from the running ACP session; their binaries were not exercised in the local probes.
