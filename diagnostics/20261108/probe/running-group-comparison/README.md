# Work card frame measurements

Headless Chromium loaded the frozen production `f67f2b01` bundle `index-DIlTXYBC.js` in a 390 × 844 touch viewport with standard Linux fontconfig and 4× CDP CPU throttling. One page contained 23 command rows and 22 reasoning rows in each of two groups. The latest group had an active command and one reasoning summary that automatically mounted its Markdown body. Each open and close finished with its actual grid transition events at the app's default configured 150 ms duration. The streaming run sent eight summary deltas at roughly 65 ms intervals, with command deltas and status events on the same isolated SSE transport. The updated text appeared in the card. All figures are from the synthetic fixture.

| Warm group | Click to open attribute | Longest frame during open | Longest frame during close | Longest close main-thread task |
| --- | ---: | ---: | ---: | ---: |
| Completed, quiet | 131–139 ms | 67 ms | 33–50 ms | <50 ms |
| Running, quiet | 146–242 ms | 33 ms | 67 ms | 102–103 ms |
| Running, receiving SSE | 758 ms | 167 ms | 150 ms | 165 ms |

The first completed opening on this fresh page took 355 ms to reach the open attribute. The first quiet running opening took 183 ms and mounted one nested Markdown body. The first opening includes work the alternating warm trials have already exercised.

The streaming opening performed 24 React commits before the open attribute, compared with four on the quiet warm openings. The eight summary events took 468 ms to arrive. Total browser Layout work over the streaming opening was 27 ms and the largest Layout event took 5.3 ms. The separately sampled V8 run attributed 116 inclusive samples to React scheduler/render work before the streaming opening versus 38 for quiet running. While closing, the source-matched `VirtualThreadMessages` ResizeObserver callback and `flushSync` were on 44 inclusive sample stacks for quiet running and streaming, versus 20 for the quiet completed control. The callback updates the virtualizer, and its commit can remeasure all mounted rows. Those samples include React work invoked synchronously by the callback. `getAnimations()` showed up during the close effect, before the animation, so it does not explain the recurring per-frame work.

The browser interception of `data-hapi-row-size` removed all writes to that diagnostic attribute and some vendor viewport `scrollHeight` reads. It left the main effect: quiet running close still had 67 ms frame gaps, the streaming close still had a 150 ms gap, and click-to-open while streaming was 736 ms. This rules out removal of the attribute alone as a sufficient fix.

The built-in `hapi-reasoning-collapsed=true` preference excluded the automatically opened Markdown body while preserving the same outer group, rows, and events. In the verified run, click-to-open while streaming fell from 758 ms to 231 ms, with six commits before opening. Manually opening the nested summary after recording displayed the last streamed event. Longest animation gaps were still 217 ms opening and 150 ms closing. The first measurement of this control similarly opened in 246 ms, with 200 ms and 133 ms frame gaps. This separates the cost of automatically rendering live reasoning before the outer group opens from the repeated work while the height transition runs.

The first staged candidate removed the explicit `flushSync` from the virtual row observer. The same 14 phases passed on `index-DVGJvRGr.js`. The quiet running close's longest animation gap fell from 67 ms to 50 ms, but its longest main-thread task still reached 95–101 ms. The streaming opening's animation gap improved from 167 ms to 83 ms while click-to-open was still 734 ms. The streaming close's gap grew from 150 ms to 183 ms. The callback's own wall time fell from 84–94 ms to 2–3 ms for quiet running close, which shows why callback time alone overstates the improvement.

On the same frozen async observer candidate, a browser-only override reused two `Intl.DateTimeFormat` instances for the exact options used by the repeated full and compact tool timestamps. Two runs redirected 835 and 843 calls. Eight reference strings per run matched the original formatting. Streaming click-to-open took 254–264 ms versus 734 ms, and total open commits fell from 42 to 25–26. The streaming close's longest animation frame was still 167 ms. This reproduces the latency gain while leaving a separate per-frame bottleneck.

The staged `index-D1BCaZcP.js` combined async row observation, shared Intl formatters and deferred live Markdown. The unprofiled run measured 227 ms streaming click-to-open and 117 ms close's longest animation gap. A second run with the V8 sampler measured 717 ms and 150 ms respectively, so the improvements were sensitive to available main-thread time. The second run exposed voice configuration calls from React effects during streaming. A follow-up fixture sent only summary deltas. It recorded three calls each to the transcription providers and voice backend endpoints while opening, and six each while closing. Opening had zero native `/items` requests in this control. `projectNativeItems` recreates an empty pending request object on every projection, invalidating the `NativeSessionPage` adapter memo and restarting the voice configuration effects that depend on that adapter.

The lean frozen baseline disabled React hooks, the global mutation log, DOM API wrappers, the CDP trace and the V8 sampler. It kept a single panel attribute listener, transition events, rAF, native long-task records and loopback API counts. Streaming opening took 1019 ms, with a 250 ms longest gap over the whole interaction and a 67 ms longest gap once the grid transition began. Streaming close still had a 150 ms longest gap during its transition. Quiet running close had 50 ms gaps versus 17–33 ms for quiet completed. These traces independently reproduce the difference without the diagnostic hooks.

The final staged build `index-BBxAUGLH.js` also keeps the Native session API adapter stable across stream events. Both lean runs passed all 14 phases and displayed the stream markers. Quiet running and completed cards had overlapping opening times of 117–140 ms and 115–123 ms. Quiet running close's longest frame fell from 50 ms to 33 ms. In the mixed stream run, click-to-open fell from 1019 ms to 632 ms and the longest gap over that interaction fell from 250 ms to 100 ms. The open transition itself had a 100 ms gap versus 67 ms previously. The longest close transition gap fell from 150 ms to 83 ms. The separate summary-only run opened in 177 ms and had 100 ms animation gaps in both directions. It made one provider/backend request pair at page initialization and zero during the observed interactions. These results show clear improvements while the 4× mixed-stream stress still produces uneven animation frames.

The final projection cache comparison uses full `item/updated` command snapshots alongside summary and status notifications. Earlier mixed trials sent standalone command output deltas, which the Native thread hook does not apply directly. Both builds received the same revised stream and consistent `/items` snapshots, and both displayed the latest summary and command stdout in the UI. The cache build `index-BOTg3R-K.js` opened in 205 ms versus 329 ms for the immutable `index-BBxAUGLH.js` baseline, before the last event at 462 ms in both trials. The longest open animation frame remained 117 ms, and the longest close frame went from 83 ms to 100 ms. Warm quiet opening was 130 ms for running and 131 ms for completed on the cache build. There were no duplicate voice configuration calls. This comparison shows an earlier response to the click, with no measured improvement to frame cadence from caching alone. See `running-group-command-items-baseline-verified/report.json` and `running-group-command-items-cache/report.json`.

The final V8 profile sampled only the streaming phases on the cache build. In the sampled 90 ms and 85 ms opening tasks and 76 ms and 74 ms closing tasks, React's scheduler appeared on 61–75 of 67–81 stacks and component rendering on 38–48 stacks. App frames include the Native history locator rebuild, `SessionChat` reduction, `StableChatTimeline.update`, composer controls, and message action bars. Assistant UI frames include its message and composer resource reconciliation and selector reads. The virtual row layout effect and its `getBoundingClientRect` calls appear on 2–4 samples per long task. The largest individual Layout events took 8.4 ms opening and 2.6 ms closing. The viewport observer appeared on three samples of a 74 ms close task. The long tasks therefore spread across rendering and committing the session, including components outside the work card. The profile does not isolate one dominant application function or a dominant standalone store flush. See `running-group-command-items-cache-profile/report.json` and `streaming-profile.json`; use the unprofiled runs for latency comparisons.

The scheduling candidate `index-2yIGIb0j.js` wraps additive live item updates in a React transition. Compared with the cache build on the same lean fixture, the longest animation gap fell from 117 ms to 67 ms when opening and from 100 ms to 67 ms when closing. The longest main-thread tasks fell from 114 ms to 102 ms and from 74 ms to 59 ms. Opening took 269 ms to begin versus 205 ms on the cache build, with the last notification arriving at 467 ms. Quiet running opening was 133 ms versus 130 ms. Both summary and stdout markers appeared, and API counts matched with zero voice configuration requests during interactions. This is one sampled run per build under 4× throttling. See `running-group-command-items-priority/report.json`.
